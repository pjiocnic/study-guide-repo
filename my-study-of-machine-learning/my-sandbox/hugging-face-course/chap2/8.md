### 1. What is the order of the language modeling pipeline?

### ❓ Question

What is the correct order of operations between a tokenizer and a model in a Transformers pipeline?

#### Choices:

1. **First, the model, which handles text and returns raw predictions. The tokenizer then makes sense of these predictions and converts them back to text when needed.**
   ❌ *Incorrect.*

   > The model **cannot understand text** directly — the **tokenizer must come first** to convert text into token IDs.

2. **First, the tokenizer, which handles text and returns IDs. The model handles these IDs and outputs a prediction, which can be some text.**
   ❌ *Incorrect.*

   > The **model's prediction is not text**. The tokenizer must be used again to convert the prediction (IDs) back into readable text.

3. **✅ The tokenizer handles text and returns IDs. The model handles these IDs and outputs a prediction. The tokenizer can then be used once again to convert these predictions back to some text.**
   ✔️ *Correct.*

   > The **tokenizer is used twice** — once to tokenize input text, and once more to decode the model’s output back to text.


### 2. How many dimensions does the tensor output by the base Transformer model have, and what are they?

### ❓ Question

What are the three dimensions of the tensor output by a Transformer model?

#### Choices:

1. **2: The sequence length and the batch size**
   ❌ *Incorrect.*

   > False! The tensor also includes a third dimension — the **hidden size**.

2. **2: The sequence length and the hidden size**
   ❌ *Incorrect.*

   > False! All Transformer models handle **batches**, even with a single input sequence — which just means the batch size is 1.

3. **✅ 3: The sequence length, the batch size, and the hidden size**
   ✔️ *Correct!*

   > This is the full shape of the model's output tensor.

### 4. What is a model head?

### ❓ Question

What is an **adaptation head** in a Transformer model?

#### Choices:

1. **A component of the base Transformer network that redirects tensors to their correct layers**
   ❌ *Incorrect.*

   > There's no such component in the architecture.

2. **Also known as the self-attention mechanism, it adapts the representation of a token according to the other tokens of the sequence**
   ❌ *Incorrect.*

   > While self-attention uses multiple **attention heads**, these are **not** the same as **adaptation heads**.

3. **✅ An additional component, usually made up of one or a few layers, to convert the Transformer predictions to a task-specific output**
   ✔️ *Correct.*

   > These are also simply called **"heads"** and are task-specific: e.g., **language modeling**, **question answering**, or **sequence classification** heads.

### 6. What are the techniques to be aware of when batching sequences of different lengths together?

### ❓ Question

Which of the following are techniques used to **batch together sequences of different lengths** into a rectangular tensor?

#### Choices:

1. **✅ Truncating**
   ✔️ *Correct.*

   > Truncation reduces longer sequences so that they fit a fixed size. It's a valid and common technique — but not the only one.

2. **Returning tensors**
   ❌ *Incorrect.*

   > Returning tensors is an outcome, not a technique for equalizing sequence lengths. It doesn’t help directly with batching.

3. **✅ Padding**
   ✔️ *Correct.*

   > Padding adds tokens to shorter sequences to match the length of the longest one. A standard method in batching.

4. **✅ Attention masking**
   ✔️ *Correct.*

   > Attention masks tell the model which parts of the input to attend to (real tokens) and which to ignore (padded tokens). Crucial for variable-length input handling.

#### Choices:

1. **It softens the logits so that they're more reliable.**
   ❌ *Incorrect.*

2. **✅ It applies a lower and upper bound so that they're understandable.**
   ✔️ *Correct.*

   > SoftMax **bounds values between 0 and 1**, making the outputs easier to interpret — though this isn’t its only benefit.

3. **✅ The total sum of the output is then 1, resulting in a possible probabilistic interpretation.**
   ✔️ *Correct.*

   > Yes! The outputs sum to 1, allowing the model to assign **probability-like scores** to each class.

### 8. What method is most of the tokenizer API centered around?

### ❓ Question

What is the **core method** of the tokenizer API in Hugging Face Transformers?

#### Choices:

1. **`encode`, as it can encode text into IDs and IDs into predictions**
   ❌ *Incorrect.*

   > While the `encode` method exists on tokenizers, **it does not exist on models** and isn't the unified API entry point.

2. **✅ Calling the tokenizer object directly.**
   ✔️ *Correct.*

   > The `__call__` method of the tokenizer is the **core entry point**. It's flexible and powerful — it supports tokenizing single or multiple sequences, padding, truncation, and more.

3. **`pad`**
   ❌ *Incorrect.*

   > Padding is important, but it's only **one component** of preprocessing — not the central method.

4. **`tokenize`**
   ❌ *Incorrect.*

   > `tokenize` is useful for viewing raw tokens, but it doesn't return IDs, masks, or attention-ready inputs — it’s not the core interface.


### ❓ Question

What does the `tokenize` method of a Hugging Face tokenizer return?

#### Choices:

1. **✅ A list of strings, each string being a token**
   ✔️ *Correct.*

   > Yes! The `tokenize` method splits the input into individual token **strings**. You can then convert these tokens to IDs and feed them to a model.

2. **A list of IDs**
   ❌ *Incorrect.*

   > This is what the `__call__` method or `convert_tokens_to_ids` is for — not `tokenize`.

3. **A string containing all of the tokens**
   ❌ *Incorrect.*

   > That would defeat the purpose — the goal is to **split** the text into tokens, not return a single joined string.

### 10. Is there something wrong with the following code?

```py

result = model(**encoded)
```

### ❓ Question

Is it okay to use a tokenizer from one checkpoint with a model from another?

#### Choices:

1. **No, it seems correct.**
   ❌ *Incorrect.*

   > Using mismatched tokenizers and models is **not advisable** — the model won't understand the token IDs it receives if they came from a tokenizer it wasn't trained with.

2. **✅ The tokenizer and model should always be from the same checkpoint.**
   ✔️ *Correct.*

   > Yes! The tokenizer and model should be from the **same checkpoint** to ensure compatibility and meaningful outputs.

3. **It's good practice to pad and truncate with the tokenizer as every input is a batch.**
   ❌ *Incorrect.*

   > While batching requires consistent shapes, **padding and truncation** are techniques used when dealing with **multiple sequences** — not just one.

### ❓ Question

Is it okay to use a tokenizer from one checkpoint with a model from another?

#### Choices:

1. **No, it seems correct.**
   ❌ *Incorrect.*

   > Using a tokenizer from a different checkpoint than the model is usually a **bad idea**. The model wasn’t trained on the token IDs produced by that tokenizer, so outputs may be meaningless (if the model runs at all).

2. **✅ The tokenizer and model should always be from the same checkpoint.**
   ✔️ *Correct.*

   > That’s right! The tokenizer and model are **trained together**, and using mismatched versions breaks this alignment.

3. **It's good practice to pad and truncate with the tokenizer as every input is a batch.**
   ❌ *Incorrect.*

   > Padding and truncation help with **batching multiple sequences**. With a single input, these may not be necessary.
