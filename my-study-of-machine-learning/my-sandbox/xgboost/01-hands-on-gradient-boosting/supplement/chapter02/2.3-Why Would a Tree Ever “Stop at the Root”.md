## 🤔 Why Would a Tree Ever “Stop at the Root”?

There are several situations where a decision tree might **not split at all** — i.e., it **stops at the root** and becomes a **"stump"** (a tree with only one node).

---

### 📌 Possible Reasons:


| Reason | Explanation |
|--------|-------------|
| **1. No other features available** | You've only given the model one feature (or none), so it can’t evaluate splits. |
| **2. All features have constant values** | The tree sees no way to separate classes (e.g., everyone has `education-num = 13`). |
| **3. Stopping criteria triggered early** | Hyperparameters like `max_depth=0`, `min_samples_split=10000`, or `min_impurity_decrease` prevent splitting. |
| **4. No split reduces impurity** | In rare edge cases, the tree may decide that **no split improves Gini or Entropy**, so it stops. |
| **5. All labels are the same** | If your data is all class 0 (or all class 1), there’s nothing to learn — the tree is already pure. |
| **6. Over-regularization** | You applied aggressive regularization (pruning, small depth, large min samples) to prevent overfitting. |

---

### 🔍 In Practice

In your census dataset, it’s **unlikely** the tree would stop at the root on its own unless:
- You accidentally dropped all features except the target
- You set a hyperparameter like `max_depth=0`

So when we **simulate a root-only prediction**, we're not saying this would happen naturally — we're saying:
> “What if we stopped here — how bad would it be?”

It's a way to **diagnose majority class bias** and appreciate why **splitting is necessary**.

---

## 🧪 Example: When Tree Stopping is Forced

```python
from sklearn.tree import DecisionTreeClassifier

clf = DecisionTreeClassifier(max_depth=0)  # Force tree to stop at root
clf.fit(X_train, y_train)

# This model will always predict the majority class
```
