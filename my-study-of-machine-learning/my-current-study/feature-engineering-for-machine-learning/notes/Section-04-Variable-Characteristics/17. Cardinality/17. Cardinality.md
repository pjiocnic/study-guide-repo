
## Cardinality definition

> **Cardinality** is the number of **unique labels** (distinct values) in a variable.
> When a variable has a large number of unique labels, it is said to have **high cardinality**.

**Example:**

* A "Country" column with 3 values — USA, Canada, Mexico — has a cardinality of **3**.
* A "Customer ID" column with 10,000 unique IDs has **high cardinality**.

---

## Impact of Cardinality on Model Training: Regression vs. Tree-Based Models

### 1. **What Cardinality Means for Models**

High cardinality (many **unique labels**) can make a big difference in how models learn — especially for **categorical variables**.
How the impact shows up depends on the model family:

---

### 2. **Regression Models (e.g., Linear / Logistic Regression)**

* **Problem:** Regression models require numerical inputs, so categorical variables are often encoded using **one-hot encoding**.
* **High cardinality effect:**

  * One-hot encoding creates **a column for each unique label** → huge feature space → **high dimensionality**.
  * Example: `"ZIP Code"` with 50,000 unique values → **50,000 extra columns** → sparse matrix, model complexity spikes.
* **Mitigation:**

  * **Frequency encoding:** Replace each ZIP code with the count or proportion of its occurrence in the dataset.
  * **Target encoding:** Replace each ZIP code with the average target value for that ZIP code.
  * **Clustering:** Group ZIP codes into broader regions (e.g., first 2–3 digits only).
  * **Hashing trick:** Use feature hashing to map many categories into a smaller fixed number of dimensions.

---

### 3. **Tree-Based Models (e.g., Decision Trees, Random Forest, XGBoost)**

* **Problem:** Trees can split directly on categorical values (if supported) or on encoded values, but…
* **High cardinality effect:**

  * Tree models may overfit to **rare categories** because they can create splits that perfectly fit tiny groups in the training data.
  * This leads to **poor generalization** when encountering new, unseen categories.
* **Mitigation:**

  * **Target or frequency encoding** (works well with trees).
  * **Group rare categories** into an `"Other"` category.
  * **Domain-based grouping** (e.g., ZIP code → region).

---

### 4. **Key Differences in Impact & Solutions**

| Aspect              | Regression Models                                        | Tree-Based Models                                             |
| ------------------- | -------------------------------------------------------- | ------------------------------------------------------------- |
| Encoding Need       | Must encode to numeric (e.g., one-hot)                   | Can handle numeric or encoded categories                      |
| Dimensionality Risk | High (many columns from one-hot encoding)                | Lower, but can still be inefficient                           |
| Overfitting Risk    | High if rare categories are overrepresented              | High if splits overly favor rare categories                   |
| Performance Impact  | Slower training, more memory usage                       | Slower training, deeper/more complex trees                    |
| **Mitigation**      | Frequency encoding, target encoding, clustering, hashing | Target encoding, frequency encoding, grouping rare categories |
